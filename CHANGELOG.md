# Changelog

Все заметные изменения проекта фиксируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
проект придерживается [Semantic Versioning](https://semver.org/lang/ru/).

## [1.10.2] — 2026-08-28

### Исправлено
- Выбор стерео-линкованной пары на вкладке Мониторинг: пульт игнорирует
  output-patch кадр, у которого источником указан правый (ведомый) канал
  пары, поэтому R-выход оставался со старым источником. Теперь линкованная
  пара роутится как в собственном экране I/O пульта — одним кадром левый
  (мастер-) канал патчится в L-выход, а правую половину пульт сам заводит
  на соседний сокет (правило odd/even пар). При клике по стерео-кнопке
  R-селектор автоматически выравнивается на соседний с L выход (L+1, если
  он не в safes). Ad-hoc пары из двух моно-каналов (Shift+клик) роутятся
  как раньше — двумя кадрами, оба канала независимые.

## [1.10.1] — 2026-08-24

### Изменено
- Демо-режим: смена сцены происходит только по кнопке «Обновить» (вместе с
  регенерацией роутинга) — периодический симулятор живых изменений сцену
  больше не трогает. Реколл пишется в журнал строкой «Scene recalled».

## [1.10.0] — 2026-08-24

### Добавлено
- Safes Output — защищённые выходы на вкладке Мониторинг: кнопка-замочек
  перед чекбоксом «Применять» открывает модалку с табами Local / SLink /
  USB / I/O Port, где каждый выход показан небольшой кнопкой с подписью,
  что в него сейчас выводится. Клик выбирает/снимает выход; на табе с
  выбранными выходами и на самой кнопке-замочке загорается красная точка.
  Список safes хранится в localStorage и переживает перезапуск программы.
- Safes-выходы недоступны для выбора в селекторах L/R: опции отключены и
  помечены 🔒; если выбранный выход добавлен в safes — выбор сбрасывается,
  автовыбор соседнего канала для R обходит safes.

## [1.9.1] — 2026-08-24

### Добавлено
- Сохранение/восстановление роутинга выходов для чекбокса «Применять» на
  вкладке Мониторинг: включение делает снимок текущего роутинга выходов
  пульта (доступно и до выбора выходов L/R), выключение — возвращает
  сохранённые патчи. Восстановление точечное: на пульт отправляются только
  патчи выходов, которые сессия реально занимала (выбранных в селекторах
  L/R, включая смену выходов посреди сессии); остальной роутинг не
  трогается. Новый IPC-метод `restoreOutputs`; ESC завершает сессию тем же
  путём.

### Изменено
- Кнопки миксов, каналов, FX и Main LR заблокированы (приглушены) до выбора
  обоих выходов L/R; чекбокс «Применять» при этом доступен.

## [1.9.0] — 2026-08-24

### Добавлено
- FX Returns на вкладке Мониторинг: ряд кнопок FX 1–4 под списком каналов
  (с тем же интервалом, что между миксами и каналами). Клик по FX-кнопке
  роутит стерео-возврат как пару — L-сторона на L-выход, R-сторона на
  R-выход. Выбор FX взаимоисключим с миксами и каналами; клик по активному
  FX — no-op, ESC снимает. Для патчей использован отдельный модификатор
  протокола (0x16/0x17) и новый IPC-метод `setFxOutputPatch`.

## [1.8.0] — 2026-08-24

### Добавлено
- Пары моно-каналов на вкладке Мониторинг: клик по каналу выбирает его на оба
  выхода L/R, затем Shift+клик по второму моно-каналу разводит пару — первый
  канал идёт на L-выход, второй на R (зелёная подсветка). Клик по члену пары
  оставляет только его (соло, на оба выхода).

### Изменено
- Клик по уже активному миксу, Main LR, стерео-паре или одиночному каналу
  больше не снимает выделение — снять всё можно только ESC (роутинг на пульте
  при этом не меняется).
- Селекторы выходов L/R стартуют без предвыбора («— не выбран —») вместо
  Local Out 1/2; пока выход не выбран, команды на пульт не отправляются.

### Исправлено
- Накопление лишних источников в аннотациях занятости выходов при
  переключении миксов/каналов: output-патчи дедуплицировались по источнику,
  тогда как инварианта пульта — один источник на физическом выходе. Патчи
  теперь ключуются по (dest, destChannel): новый патч вытесняет предыдущий
  источник этого выхода, а один источник может идти на несколько выходов.
  Заодно исправлена демо-сцена, где FX L и R были заведены на один выход.

## [1.7.0] — 2026-08-24

### Добавлено
- Признак занятости выходов в селекторах L/R вкладки Мониторинг: рядом с
  меткой выхода, на который что-то назначено, показывается источник из
  текущего роутинга пульта — например «Local Out 1 · Main LR». Свободные
  выходы остаются с чистой меткой. Данные берутся из снапшота роутинга
  (output-патчи шин, FX return и мониторов), обновляются в реальном времени;
  при конфликте (несколько источников на одном выходе) метки склеиваются
  через « + ».

## [1.3.0] — 2026-08-20

### Добавлено
- Живые уровни сигнала (метры) в таблице ACTIVE PATCHING: горизонтальный бар
  (зелёный → янтарный → красный), значение в дБ и красная точка перегруза (clip).
  Данные декодируются из UDP-потока метров, который пульт шлёт после хендшейка.
- Пакеты декодируются в main-процессе (`src/main/meters.ts`): id=0x06 (48×11
  слотов) и id=0x17 (по одному уровню на вход); уровень = (значение − 0x8000)/256
  дБ, 0x1201 — «нет сигнала», клип — выше 0 дБFS. Значения проверены на реальном
  захвате трафика пульта.

### Изменено
- UDP-слушатель в `connection.ts` теперь декодирует метро-пакеты и эмитит
  событие `meters`; main-процесс пробрасывает их рендереру через IPC, рендерер
  объединяет поток (~25–50 пакетов/с) в один кадр обновления.

## [1.1.0] — 2026-08-20

### Добавлено
- Кнопка A/B Swap в колонке переноса: одним нажатием меняет роутинг на пульте.
  Целевой список определяется по-последнему загруженному на пульт; если ни один
  список ещё не загружался, применяется активный. Кнопка активна только когда
  списки A и B различаются.
- Вспышка заголовка "Active Patching" при смене роутинга окрашивается в цвет
  применённого списка (синий — список A, зелёный — список B).

### Изменено
- Списки A и B заполняются роутингом пульта сразу при подключении, а не
  «лениво» при первом переключении. Неиспользованный соседний слот намертво не
  блокируется пустой запечатанной копией — данные подтягиваются по завершении
  начальной загрузки.
- При загрузке сохранённого роутинга в один список соседний (если ещё пуст)
  заполняется роутингом пульта, чтобы кнопка свапа сразу стала доступной.
- Отправка патчей на пульт вынесена в единый `sendPatchesToConsole`, общий для
  Upload и Swap.
