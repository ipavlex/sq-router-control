# Вкладка «Журнал» — описание работы

> Подробное описание вкладки «Журнал» (журнал кадров и событий): интерфейс,
> формат строк, уровни, счётчик обновлений, метки, жизненный цикл и источники
> записей. Справочник по протоколу SQ — в [`SQ-PROTOCOL.md`](SQ-PROTOCOL.md).

## 1. Назначение

Вкладка «Журнал» — это потоковая (in-memory) лента событий приложения и
обмена с пультом. Она нужна для:

- контроля подключения и демо-режима (кто подключился, когда оборвалось);
- наблюдения за роутингом (какие патчи отправлены, какие сцены реколлнуты);
- диагностики протокола на реальном пульте: сводки Initial state, блок
  routing/config, инвентарь meter-пакетов, сырые DSP-кадры;
- разметки эксперимента **метками** (`M`), чтобы связать строки с действиями
  на пульте («нажал метку, когда сигнал ушёл в Mix 5»).

Журнал ведётся **только в памяти renderer-процесса**. Он не пишется на диск,
не сохраняется между сессиями и очищается при входе в дашборд.

Точки входа в коде:
- renderer: `src/renderer/tabs/log/index.ts`, `src/renderer/tabs/log/view.html`;
- источник событий: main-процесс `src/main/main.ts` → `sq:log`;
- мост: `src/main/preload.ts` (`onLog`) → `src/renderer/dashboard/index.ts`.

## 2. Интерфейс

### Кнопка в топбаре

| Элемент | Состояние | Действие |
|---|---|---|
| `📋 Журнал` (`#log-btn`) | вкладка скрыта | открыть журнал и проскроллить вниз (`dashboard/index.ts:80-84`) |
| `← Назад` | вкладка открыта | вернуться на вкладку «Роутинг» |

Текст кнопки переключается в `showView()` (`src/renderer/core/utils.ts:196-205`).
Пока журнал открыт, вкладка «Роутинг» переключается тем же верхним рядом
кнопок `🔊 Роутинг` / `🎧 Монитор`.

### Панель журнала

Заголовок «Журнал кадров» (`src/renderer/tabs/log/view.html`):

| Элемент | Роль |
|---|---|
| `#update-stat` (`.stat`) | Счётчик: `обновлений: N · routing block: X B` |
| `Метка (M)` (`#mark-log`) | Вставить видимый разделитель-метку в ленту |
| `Очистить` (`#clear-log`) | Полностью очистить ленту и счётчик |
| `#log` (`.log`) | Прокручиваемая область строк (flex, на всю высоту) |

Панель растягивается на всю высоту вьюпорта (`.log-view` отменяет боковые
рамки и скругления, `src/renderer/assets/styles.css:75-88`).

## 3. Формат строки

Каждая строка — `<div class="line">` из трёх колонок (`pushLog`,
`src/renderer/tabs/log/index.ts:21-29`):

```
[HH:MM:SS] [LEVEL]  сообщение
```

| Колонка | Класс | Описание |
|---|---|---|
| Время | `.ts` | Локальное время `HH:MM:SS` (`fmtTime()`), без даты |
| Уровень | `.lvl <level>` | Верхний регистр уровня, фиксированная ширина 52px |
| Сообщение | `.msg` | Текст, экранируется через `escapeHtml()` (защита от HTML в именах каналов) |

Сообщение стилизуется `white-space: pre-wrap`, поэтому многострочные сводки
(например, `Channel state …`) переносятся, а не обрезаются.

### Уровни

`LogLevel = "dsp" | "frame" | "ok" | "warn" | "error"` (`src/shared/ipc.ts:141`).

| Уровень | Цвет | Смысл | Типичные записи |
|---|---|---|---|
| `OK` | зелёный | успешное действие/состояние | «Connected to …», «Демо-режим…», «Scene recalled» |
| `WARN` | янтарный | некритичная проблема | «Disconnected from mixer.», «Demo mode stopped.» |
| `ERROR` | красный | ошибка | «Connection error: …», «Demo simulation error: …» |
| `FRAME` | акцентный (синий) | протокольный кадр/сводка | «Routing/config block…», «Meter packet…», «Initial state burst complete…» |
| `DSP` | приглушённый | отправленная команда/сырой кадр | «Input … → …», «PAFL …», «DSP  f7 0b …» |

Цвета — `styles.css:982-1002`.

### Метки

`mark()` (`log/index.ts:38-47`) добавляет строку `MARK` с подсветкой
(фон + рамка сверху/снизу, `styles.css:1010-1022`) и сквозным номером:
`——— метка №N ———`. Счётчик `markCount` начинается с 1 и сбрасывается только
через «Очистить» — нумерация переживает вход/выход из вкладки.

## 4. Буфер и прокрутка

- **Лимит**: `MAX_LOG_LINES = 400` строк. При переполнении самые старые строки
  удаляются (FIFO) — счётчик `logLineCount` синхронизирован с DOM
  (`log/index.ts:8-18`).
- **Автоскролл**: после каждой записи лента прокручивается в конец
  (`elementRefs.log.scrollTop = scrollHeight`), даже если вкладка скрыта.
- **Записи копятся фоном**: `pushLog` не проверяет видимость вкладки, поэтому
  пока пользователь на «Роутинге», лента продолжает наполняться. При открытии
  журнала выполняется дополнительный скролл вниз.
- **Ограничение**: строки не отфильтровываются и не группируются — уровни
  (`dsp`/`frame`) идут вперемешку с пользовательскими событиями.

## 5. Счётчик обновлений

`updateStat(snapshot)` (`log/index.ts:56-62`) вызывается из
`dashboard/index.ts:60` на каждый `sq:routing` и выводит в заголовке:

- `обновлений: <updates>` — число обновлённых слотов за последний снапшот;
- `routing block: <bytes> B` — размер routing/config-блока, если известен.

Поля берутся из `SnapshotPayload` (`updates`, `routingBlockBytes`). При
«Очистить» текст счётчика сбрасывается.

## 6. Очистка и жизненный цикл

| Событие | Что происходит |
|---|---|
| Вход в дашборд (`enterDashboard`) | `log.clear()` — лента, счётчик строк, номер метки и `#update-stat` сбрасываются (`dashboard/index.ts:30`) |
| Кнопка «Очистить» | то же, что `clear()` (`log/index.ts:49-54`) |
| Отключение / разрыв | лента не чистится; в неё лишь добавляется `WARN`/`ERROR` |
| Переподключение | `enterDashboard` вызывается заново → журнал очищается |

Подписка на поток событий — однократная, на уровне модуля:
`window.sq.onLog((p) => log.pushLog(p.level, p.msg))` (`dashboard/index.ts:70`).

### Горячая клавиша `M`

Обработчик навешивается при загрузке модуля (`log/index.ts:67-76`):

- срабатывает, только когда вкладка «Журнал» видима;
- игнорирует нажатие в `input`/`select`/`textarea`;
- использует `e.code === "KeyM"` — не зависит от раскладки (работает и в
  русской раскладке, где физическая клавиша даёт «Ь»).

## 7. Источники записей

Все события приходят из main-процесса через IPC-канал `sq:log` (payload
`{ level, msg }`) и попадают в renderer через `window.sq.onLog`. Ниже —
карта основных источников (все — `src/main/main.ts`).

### Подключение и сессия

| Событие | Уровень | Строка |
|---|---|---|
| Подключение к пульту | `ok` | «Connected to <model> (FW …) at <host>» |
| Разрыв связи | `warn` | «Disconnected from mixer.» |
| Ошибка соединения | `error` | «Connection error: …» |
| Старт демо | `ok` | «Демо-режим: симуляция …» |
| Остановка демо | `warn` | «Demo mode stopped.» |

### Роутинг и патчи

| Действие | Уровень | Пример |
|---|---|---|
| Input patch | `dsp` | «Input 7 → Local 7» |
| Output patch (канал/микс/LR/матрица) | `dsp` | «Route Mix 3 → SLink Out 1» |
| FX output patch | `dsp` | «Route FX1 L → USB Out 1» |
| Monitor patch (PAFL L/R) | `dsp` | «Monitor PAFL L → Local Out 7» |
| PAFL включение/выключение | `dsp` | «PAFL Mix 5: ON» |
| Загрузка сохранённого роутинга | `ok` | «Загружен роутинг: N патчей применено…» |
| Восстановление выходов | `ok` | «Восстановлен роутинг выходов: N патчей…» |
| Запрос полного дампа | `frame` | «Requested full routing/state dump…» |
| Изменения в демо-симуляции | `dsp` | «Routing change: …» |

### Сцены

| Событие | Уровень | Пример |
|---|---|---|
| Реколл по live-кадру | `ok` | «Scene recalled: 2 — Sunday Service» |
| Реколл по записи сцены | `frame` | «Scene recalled: 2 — Sunday Service» |
| Сводка списка сцен | `frame` | «Scene list: N slots, M named…» |
| Демо: реколл сцены | `ok` | «Scene recalled: 2 — Sunday Service» |

### Диагностика протокола

| Событие | Уровень | Пример |
|---|---|---|
| Завершение Initial state burst | `frame` | «Initial state burst complete. Frames: total=…» |
| Итог декодирования роутинга | `ok` | «Routing decoded: N input patches…» |
| Состояние каналов из дампа | `ok` | «Channel state from initial dump: …» |
| Routing/config-блок | `frame` | «Routing/config block (sub=0x10): N bytes received» |
| Инвентарь meter-пакетов | `frame` | «Meter packet: id=0x… body=…B…» |
| Сырые DSP-кадры | `dsp` | «DSP  f7 0b 0b 0d …» (первые 8 байт hex) |
| Сохранение диагностических дампов | `frame` | «Diagnostics: ParamData saved…», «Diagnostics: meter packet saved…» |

Диагностические файлы (`ParamData`, meter-дампы) сохраняются main-процессом в
`<userData>/diagnostics`; в журнал пишутся только их пути и сводки.

## 9. Ограничения

- Журнал **не экспортируется** и не сохраняется на диск — только экран.
- Время без даты; при длительной сессии единственная привязка — порядок строк и
  метки.
- Лимит 400 строк: ранние диагностические сводки при долгой работе вытесняются
  частыми `dsp`/`frame`-записями.
- Нет фильтрации по уровню и поиска по тексту.
- Счётчик `обновлений` показывает состояние **последнего** снапшота, а не сумму
  за сессию.
