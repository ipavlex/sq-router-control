# Вкладка «Монитор» — описание работы

> Подробное описание работы вкладки «Монитор»: интерфейс, логика маршрутизации,
> безопасность выходов, уровневые метры, навигация.
> Справочник по протоколу SQ — в
> [`SQ-PROTOCOL.md`](SQ-PROTOCOL.md).

## 1. Назначение

Вкладка «Монитор» позволяет направить любой источник (входной канал, микс,
Main LR, FX return) на конкретный физический выход пульта — для контроля
на мониторных колонках или наушниках.

Ключевые свойства:
- **Неразрушающий режим**: снятие выбора источника **не меняет** роутинг —
  выходы сохраняют последний назначенный источник;
- **Сессионная отмена**: тумблер «Применять» включает/выключает отправку
  команд на пульт; при выключении всё восстанавливается до начала сессии;
- **Безопасные выходы** («safes»): выходы, которые приложение не имеет права
  переназначать — блокируются в селекторах и запоминаются между сессиями.

## 2. Интерфейс

### Панель управления

Расположена вверху вкладки:

| Элемент | Роль |
|---|---|
| 🔒 (кнопка-замок) | Открытие модального окна выбора «безопасных» выходов |
| «Применять» (тумблер) | Включение/выключение отправки команд на пульт |
| L (селектор) | Выход для левого канала (Local Out, SLink Out, USB Out, I/O Port Out) |
| R (селектор) | Выход для правого канала |
| Main LR (кнопка) | Быстрый выбор Main LR как источника |

### Группы кнопок источников

| Группа | Источники | Особенности |
|---|---|---|
| **Миксы** | Mix 1–12, Main LR | Стерео-миксы показывают 2 бара (L \| R), моно — 1 бар |
| **Каналы** | Входы 1–48 | Стерео-пары объединены в одну широкую кнопку; моно-каналы — одинарные |
| **FX returns** | FX 1–4 | Стерео-источники (L → L-выход, R → R-выход) |

## 3. Селекторы выходов

### Доступные типы выходов

Селекторы L и R содержимое зависит от модели пульта:

| Группа | Тип | Адрес | Кол-во | Примеры |
|---|---|---|---|---|
| **Local Out** | `0x1a` | XLR | SQ-5: 12, SQ-6: 14, SQ-7: 16 | Local Out 1…16 |
| **TRS Out** | `0x1a` | TRS (A/B) | 2 на всех моделях | TRS Out A, TRS Out B |
| **SLink Out** | `0x1c` | — | 48 | SLink Out 1…48 |
| **USB Out** | `0x1d` | — | 32 | USB Out 1…32 |
| **I/O Port Out** | `0x1e` | — | 64 | I/O Port Out 1…64 |

TRS Out продолжают нумерацию XLR: например, SQ-5 (12 XLR + TRS A = Local Out 13,
TRS B = Local Out 14). Оба используют адрес `0x1a`.

### Автоматический выбор правого выхода

При выборе L-выхода R-селектор автоматически переключается на соседний
(том же банке, номер + 1) — по правилу нечёт/чёт пульта. Если соседний
выход заблокирован (safes), автоматический выбор не происходит.

### Аннотации использования

Каждый пункт селектора показывает текущий источник:
- `Local Out 1` — выход свободен;
- `Local Out 1 · Kick` — выход уже маршрутизирован (из снапшота роутинга);
- `Local Out 1 · Kick · 🔒` — выход заблокирован (safe).

## 4. Логика маршрутизации

### Типы источников и их поведение

| Тип | L-выход | R-выход | Комментарий |
|---|---|---|---|
| **Стерео-пара** (линк на пульте) | Левый канал (master) | *(правый — автоматически пультом)* | Патчится только master-канал; SQ сам ганgit правый на соседний сокет |
| **Ад-хок стерео** (Shift+клик) | Первый канал | Второй канал | Ручная пара из двух моно-каналов |
| **Моно-канал** | Канал | Канал | Один источник в оба выхода |
| **Микс** | Микс (b3: `0x58`–`0x63`) | Микс | Один источник в оба выхода |
| **Main LR** | Main LR (b3: `0x68`) | Main LR | Один источник в оба выхода |
| **FX return** | L-сторона (FX engine) | R-сторона | Стерео-источник, L/R разделяются |

### Формирование патч-кадров

Маршрутизация выполняется через DSP-кадры патчинга:
- **Output patch** (`window.sq.setOutputPatch`): обычные источники (каналы, миксы, LR);
- **FX output patch** (`window.sq.setFxOutputPatch`): FX returns — отдельный тип кадра.

### Взаимное исключение

Выбор источников обоюдно исключающий:
- Выбор **микса** сбрасывает выбор каналов и FX returns;
- Выбор **канала** сбрасывает миксы и FX returns;
- Выбор **FX return** сбрасывает миксы и каналы.

При снятии выбора (клик по активному элементу) — **ничего не происходит**
(остаётся текущий выбор; полный сброс — через `Esc`).

## 5. Тумблер «Применять»

Работает как **сессия с откатом**:

### Включение (checked → true)

1. Снимает текущий роутинг выходов (snapshot);
2. Запоминает все выбранные L/R выходы как «заимствованные»;
3. Начинает отправку патч-кадров на пульт.

### Выключение (checked → false)

1. Восстанавливает **только заимствованные** выходы — те, которые были
   выбраны во время сессии;
2. Выходы, которые пользователь не трогал, остаются без изменений;
3. Очищает состояние сессии.

### Ключевые свойства

- Снимок роутинга берётся **при включении** — до отправки первых команд
  маршрутизации (тумблер доступен только после выбора хотя бы одного выхода);
- Выбранные после включения выходы **добавляются** в список заимствованных
  (и будут восстановлены при выключении);
- Если ни один выход не выбран — тумблер заблокирован (вместе с кнопками
  источников).

## 6. Безопасные выходы (Safe Outputs)

### Назначение

Выходы, которые **не переназначаются** приложением: мониторы звукорежиссёра,
основная запись и т.п.

### Модальное окно

Открывается кнопкой 🔒. Содержит вкладки:

| Вкладка | Тип выходов |
|---|---|
| Local | XLR + TRS (`0x1a`) |
| SLink | SLink Out (`0x1c`) |
| USB | USB Out (`0x1d`) |
| I/O Port | I/O Port Out (`0x1e`) |

Каждая вкладка — сетка кнопок с номерами/буквами выходов. Кнопка показывает:
- Номер/букву выхода;
- Текущий маршрутизированный источник (из снапшота);
- Статус: выбранная кнопка получает стиль `.selected`.

### Поведение

- **Заблокированные выходы** отключены в селекторах L/R (выбрать невозможно);
- Если текущий L/R выбор стал safe — он **автоматически снимается**;
- Маркер 🔒 появляется в селекторе напротив safe-выхода;
- Красная точка на кнопке 🔒, пока хотя бы один выход выбран;
- Красная точка на вкладке, если в ней есть хотя бы один safe-выход.

### Сохранение

- Хранится в `localStorage` под ключом `sq_safe_outputs`;
- Формат: массив строк `"destType:destChannel"` (десятичные числа);
- **Переживает перезапуск** приложения.

## 7. Уровневые метры

### Вертикальные бары

На каждой кнопке источника — тонкий вертикальный бар слева. Растёт снизу
вверх; клип-флаг загорается сверху.

| Тип кнопки | Кол-во баров | Источник данных |
|---|---|---|
| Моно-канал | 1 | `inputs[b3]` |
| Стерео-канал | 2 (L, R) | `inputs[b3L]`, `inputs[b3R]` |
| Моно-микс | 1 | `mixes[mixIdx]` |
| Стерео-микс | 2 (L, R) | `mixesL[mixIdx]`, `mixesR[mixIdx]` |
| Main LR | 2 (L, R) | `mainLRL`, `mainLRR` |
| FX return | 0 | *(нет метра — стерео-возврат, уровень не отображается)* |

### Шкала

Одна шкала для всех вкладок (shared `meters.ts`):
- Диапазон: −60…0 дБФС → 0–100% высоты бара;
- ≥ −20 дБ: жёлтый (`meter-warn`);
- ≥ −6 дБ: красный (`meter-hot`);
- Клип (> 0 дБ): индикатор `.ch-meter-clip.on`.

### Кеширование по кадрам

UDP-поток метров приходит на 25–50 Гц. Renderer кеширует последний пакет
(`pendingMeters`) и применяет его в `requestAnimationFrame` — одна операция DOM
на каждый кадр экрана.

### Стерео-детект миксов

Стерео-микс определяется двумя путями:
1. **Из снапшота**: таблица `mixStereoPairs` (декодирована из ParamData);
2. **Поведенчески**: если `|L − R| ≥ 0.4 дБ` — защёлкивается как стерео
   на всю сессию (моно-шины метрируют L/R бит-в-бит, ложных срабатываний нет).

При обнаружении нового стерео-микса — `buildMixButtons()` пересоздаёт
контейнер (добавляет второй бар). Предыдущие показания сразу
пере-применяются (`lastMeters`).

## 8. Горячие клавиши

| Клавиша | Действие |
|---|---|
| `←` / `→` | Переключение между каналами (если канал активен) или миксами (если микс активен); зациклено |
| `1`–`9` | Активация Mix 1–9 (только включение, не выключение) |
| `0` | Активация Mix 10 |
| `Esc` | Полный сброс: выключение «Применять», снятие всех выделений (при уже выключенном «Применять» — бездействует) |

Сочетания:
- `Shift+клик` по моно-каналу → ад-хок стерео-пара (первый → L, второй → R);
- `Shift+клик` по стерео-паре → перезапуск (не создаёт ад-хок);
- `Esc` при открытом модальном окне safes → только закрытие окна.

## 9. Демо-режим

В демо-режиме уровни синтезируются (`demo-meters.ts`):

- **Каналы**: медленный random-walk вокруг номинального уровня + пиковые всплески;
- **Стерео-пары**: L/R коррелируют (δ ≤ 1.2 дБ);
- **Миксы**: наследуют уровень от горячего контрибьютора (−6…−1 дБ);
- **Main LR**: больше контрибьюторов, меньше headroom, всегда стерео;
- **Стерео-миксы**: L/R расходятся (δ ≤ 1.5 дБ), моно — бит-идентичны.

Такт симуляции: 200 мс (5 пакетов/с).

## 10. Протокол и данные

### Команды, отправляемые на пульт

| Команда | Где в коде | Назначение |
|---|---|---|
| `setOutputPatch(sourceB3, destType, destChannel)` | `routeSourceToOutput()` | Патч обычного источника на выход |
| `setFxOutputPatch(fxIndex, side, destType, destChannel)` | `routeFxToOutput()` | Патч FX return на выход |
| `restoreOutputs(outputs)` | `onMonEnableChange()` | Восстановление роутинга при выключении «Применять» |

### Адреса источников (b3)

| Источник | Диапазон b3 | Комментарий |
|---|---|---|
| Входные каналы | `0x00`–`0x2F` (0–47) | 48 каналов (local + SLink + USB) |
| FX returns | `0x40`–`0x43` | FX 1–4 (stereo: L=engine, R=engine+1) |
| Миксы | `0x58`–`0x63` | Mix 1–12 |
| Main LR | `0x68` | Стерео |

### Поток метров (`MetersPayload`)

| Поле | Источник | Применение в мониторе |
|---|---|---|
| `inputs[]`, `clip[]` | UDP 0x06/0x17 | Канальные бары |
| `mixes[]`, `mixClip[]` | UDP 0x18 (моно-режим) | Моно-микс-бары |
| `mixesL[]`, `mixesR[]` | UDP 0x18 | Стерео-микс-бары (L/R) |
| `mixClipL[]`, `mixClipR[]` | UDP 0x18 | Клип-флаги стерео-миксов |
| `mainLR`, `mainLRClip` | UDP 0x18 (шина 23) | Main LR (моно-фоллбэк) |
| `mainLRL`, `mainLRR` | UDP 0x18 | Main LR стерео (L/R) |

## 12. Известные ограничения

1. **FX returns** не показывают уровневых баров — данные о FX-шинах в
   metro-потоке не выделены (нет декодера FX send-метров в 0x18);
2. **«Применять»** не отслеживает изменения, внесённые на пульте вручную
   во время сессии — снимок берётся один раз при включении;
3. **Safe outputs** хранятся в localStorage — недоступны при работе
   через разные профили Electron;
4. **Горячие клавиши** стрелок не работают при фокусе на select/input;
   number keys — только для миксов 1–10 (Mix 11–12 только кликом).
