# SQ-METERS — CLI-тула UDP-метров

`tools/sq-meters.ts` — автономная CLI-тула для обработки метро-потока пульта
(без Electron). Подключается так же, как приложение: TCP-хендшейк с обменом
UDP-портами (MeterSub, sub=0x00), дальше слушает UDP-дейтаграммы — те же
пакеты, что декодирует `src/main/meters.ts`. Формат и известные id — в
[`SQ-PROTOCOL.md`](SQ-PROTOCOL.md) §8.

## 1. Команды

| Команда | Что делает |
|---|---|
| `npm run sq-meters -- watch <host> [port]` | Живой вид: раз в `--every` мс (по умолчанию 500) печатает строку расшифрованных метров — входы, Main LR, Mix 1–12; при первом появлении каждой формы пакета печатает её инвентарную строку |
| `npm run sq-meters -- capture <host> [port]` | Слушает окно `--duration` (по умолчанию 10000 мс) и сохраняет по одному сырому `.bin` на каждую форму пакета + отчёт `report.txt` |
| `npm run sq-meters -- decode <file.bin>` | Офлайн-разбор одной сырой дейтаграммы (принимает и файлы capture, и дампы приложения `<userData>/diagnostics/meter-packet-*.bin`); `--full` печатает все слоты тела (raw hex + дБФС) |

Опции: `--duration <ms>`, `--timeout <ms>` (хендшейк), `--every <ms>` (watch),
`--out <dir>` (по умолчанию `meter-dumps/`), `--label <name>` (capture).

## 2. Строка живого вида

```
15:32:07 In: [3]-12.4 [5]-3.2 [8]-0.1!  |  LR: L-6.5 R-7.8  |  Mix: 1:-4.8/-6.5 3:-12.0/-
```

- слоты входов — 1-based номера каналов, `!` — клип (> 0 дБФС);
- клип-флаги входов приходят только из пакета `0x06` (детального), для
  `0x17`-файла их не будет — как в приложении;
- `-inf` — пол (сентинел `0x1201`), тихие слоты не печатаются.

## 3. Инвентарь форм и охота за слотами

Каждая уникальная форма (id + длина тела) при первом появлении печатается:

```
  shape id=0x06 body=1056B (decoded)
  shape id=0x07 body=1416B (undecoded)  dB [0]-inf … [8]0.1 …  hot: [8]-2.3 [23]-3.1
  shape id=0x07 body=1416B (undecoded)  chg: [8]-14.2 [23]-3.1
```

Для недекодированных форм (`0x07`, `0x09`, `0x16`) тул повторяет снимок раз
в ~4 с (как `_noteMeterPacket` в приложении): `hot:` — самые горячие слоты,
`chg:` — слоты, сдвинувшиеся с прошлого снимка. Методика та же, что дала
расшифровку `0x18` (см. `SQ-PROTOCOL.md` §8.4/§8.6): подать сигнал в **одну**
известную шину за раз — верхний слот `hot:` или двигающийся слот `chg:`
прямо называет, где живёт уровень этой шины.

## 4. Файлы capture

```
meter-dumps/cap-<дата-время>[-label]/
  meter-packet-0x06-1056B.bin   # по одному сырому дейтаграмме на форму
  meter-packet-0x07-1416B.bin
  report.txt                    # шапка сессии, таблица форм, последний
                                # payload, снимки недекодированных форм
```

Имена совпадают со схемой дампов приложения (`meter-packet-0x<id>-<len>B.bin`
в `<userData>/diagnostics`), поэтому `decode` работает с обоими источниками.

## 5. Ограничения

- Реальное соединение требует пульта в сети (группа B): `watch`/`capture`
  проверяются только на живом SQ; офлайн проверяется `decode`.
- id/раскладки метро-пакетов не переносятся между моделями семейства A&H —
  не переносить выводы с SQ-5 без проверки (см. `SQ-PROTOCOL.md` §11).
- Тул ничего не пишет на пульт: только хендшейк-подписки, как приложение.
