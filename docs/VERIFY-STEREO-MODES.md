# Проверка режима моно/стерео миксов и матриц (ParamData)

> Инструкция для контролируемого подтверждения того, как в дампе ParamData
> закодирован режим **моно/стерео** миксов и матриц. Нужна, потому что часть
> полей определена косвенно (по двум снимкам), а часть пока не найдена.
> Ссылки на исходные находки — в [`SQ-PROTOCOL.md`](SQ-PROTOCOL.md) §8.5 и §10.2.

## 1. Текущий статус

| Объект | Поле | Статус |
|---|---|---|
| Миксы (Mix 1–12, b3 `0x58–0x63`) | байт `+331` блока канала (`884 + b3·336 + 331`) | режим подтверждён на двух снимках; **полярность** (`1 = стерео`) ожидает подтверждения |
| Матрицы (b3 `0x73–0x78`) | в блоке канала `+331` всегда `0` | **не найдено**; стерео видно как encoding-A пары (`[b3][0f][fe][b3][10][fe]`) в link-регионе |

Основания (одинаковый layout блоков `884 + b3·336`):

- дамп консоли SQ-5 (`paramdata-dump.bin`, 97 376 Б): `+331 = 1` у Mix 1–10 (5 пар);
- show-файл MixPad (`NVDATA.DAT`, 131 072 Б): `+331 = 1` у Mix 1–8 (4 пары);
- в обоих снимках `+331` — **единственный** байт блока, согласованно отделяющий
  набор стерео-миксов от моно; набор всегда чётный префикс списка (так и
  аллоцируются стерео-пары);
- у матриц в блоке `+331 = 0`, а в link-регионе A-пары найдены только для
  `0x73/0x74` (`0x75` не линкован).

Смысл полярности `1 = стерео` выведен из того, что сконфигурированные миксы
равны `1`, а пустые хвостовые — `0`. Это и проверяется экспериментом ниже.

## 2. Инструменты и ограничения

- **CLI-тула `sq-dump` (v1.20.0) снимает ограничения этого раздела** — приложение
  для дампа больше не нужно:
  ```bash
  npm run sq-dump -- capture 192.168.1.30 --label baseline   # дамп + отчёт
  # …меняем ОДНУ настройку на пульте…
  npm run sq-dump -- capture 192.168.1.30 --label experiment
  npm run sq-dump -- diff pd-dumps/pd-*-baseline.bin pd-dumps/pd-*-experiment.bin
  ```
  `diff` печатает каждый изменившийся байт с расшифровкой региона (блок канала
  +offset, fader-секция, link-таблица, регион линков шин) и подсказку-вердикт
  для чистых экспериментов. Дампы пишутся в `pd-dumps/` (git-ignored) с
  меткой времени и `--label`. `info <bin>` — полный отчёт диагностики.
- Ограничение основного приложения (оставлено как есть): дамп пишется **один**
  раз за соединение (`_initialStateParsed` в `connection.ts` сбрасывается
  только в `connect()`); для нового дампа — переподключение. Туле это не
  важно: она на каждое снятие делает своё соединение.
- macOS-пути дампов приложения (если используется оно):
  `~/Library/Application Support/sq-router-control/diagnostics/`
  (`paramdata-dump.bin`, `paramdata-stereo.txt` — перезаписываются).

**Вывод:** базовый способ — тулой выше; приложение — запасной путь.

## 3. Процедура (менять ровно одну настройку за раз)

### 3.1. Полярность миксов
1. `npm run sq-dump -- capture <host> --label pdA`
2. На пульте перевести **один** микс, желательно заведомо моно (в эталонном
   дампе — Mix 12, `+331 = 0`), в **стерео**. Больше ничего не трогать.
3. `npm run sq-dump -- capture <host> --label pdB`
4. `npm run sq-dump -- diff pd-dumps/pd-*-pdA.bin pd-dumps/pd-*-pdB.bin`
   Ожидание: одиночное изменение байта `abs = 884 + b3·336 + 331` у Mix 12,
   `0 → 1` (вердикт «polarity 1 = stereo» тула напечатает сама).
   Для микса `N` адрес: `b3 = 0x57 + N`, `abs = 1215 + 336·N`
   (Mix 1 = 30783 … Mix 12 = 34479).

### 3.2. Режим матриц
1. Снять baseline `--label pdA` (матрицы в эталонных дампах стерео).
2. На пульте **разбить одну** матрицу в моно (например, Matrix 3), не трогая
   миксы и остальные матрицы.
3. Снять `--label pdB` и сравнить `diff`-ем.
4. `+331` в блоке матрицы **не изменится** — ищите изменение в блоке канала
   `884 + b3·336` (`b3` из `0x73–0x78`) вне `+331`, а также в
   link-регионе (~`81292`, `81548`, `82060+`). Diff пометит такие адреса как
   «bus link region»; полный контекст — в секции «Bus link regions» отчётов
   `.txt` обоих дампов. Найденный офсет и будет полем режима матрицы.

## 4. Как читать diff

- Блок канала: `884 + b3·336`; внутри документально известны `+96/97` фейдер
  (в 300-байтовой секции `43520 + b3·300`), `+331` — режим микса,
  `+332` — флаги (bit0 полярность, bit1 mute).
- Стерео-линки входов — таблица `81548` (encoding A/B, см. `stereo-links.ts`).
- Если менялась одна настройка, «шум» diff минимален; любые посторонние
  изменения — от живого сигнала/фейдеров, их лучше не трогать в процессе.

## 5. Ускоритель — реализован (v1.20.0)

Всё из этого списка сделано в CLI-туле `tools/sq-dump.ts`
(`npm run sq-dump -- …`, см. §2):

- дамп по отдельному соединению — без переподключений основного приложения;
- файлы с меткой времени и `--label` (A/B живут одновременно, `pd-dumps/`);
- встроенный `diff` с расшифровкой «регион + offset + b3» и вердиктами для
  чистых экспериментов (одиночный `+331` у микса / изменения только в
  регионе линков шин).
