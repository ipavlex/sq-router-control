# Вкладка «Роутинг» — описание работы

> Подробное описание работы вкладки «Роутинг»: интерфейс, таблицы Active/Input
> Patching, редактируемые пресеты A/B, Upload/Download, сохранение/загрузка
> роутинга, уровневые метры, синхронная прокрутка.
> Справочник по протоколу SQ — в
> [`SQ-PROTOCOL.md`](SQ-PROTOCOL.md).

## 1. Назначение

Вкладка «Роутинг» предоставляет полный контроль над **input patching** пульта
Allen & Heath SQ — физическим назначением источников (Local, SLink/dSnake, USB,
I/O Port) на входные каналы микшера (Input 1–48).

Ключевые свойства:
- **Двухпанельная компоновка**: слева — редактируемый Input Patching (для
  подготовки изменений), справа — Active Patching (отображает текущий роутинг
  на пульте с уровневыми метрами);
- **Два пресета (A/B)**: каждый пресет хранит собственную конфигурацию
  инпатчинга; быстрое переключение между ними кнопкой Swap;
- **Upload / Download**: Upload отправляет выбранные каналы из Input Patching
  на пульт; Download переносит текущий роутинг пульта в Input Patching;
- **Сохранение/загрузка**: именованные снапшоты роутинга хранятся в
  localStorage и доступны для быстрого восстановления;
- **Заморозка после старта**: после начального заполнения состояния пульта
  Input Patching замораживается — изменения на пульте не затрагивают таблицу,
  но селекторы остаются редактируемыми.

## 2. Интерфейс

### Компоновка

Вкладка состоит из трёх горизонтальных областей:

| Область | Расположение | Содержимое |
|---|---|---|
| **Input Patching** | Левая панель | Редактируемая таблица с селекторами источников и входов; кнопки Сохранить/Загрузить |
| **Панель управления** | Центр (между панелями) | Кнопки A/B, Swap, Upload (→), Download (←), синхронная прокрутка |
| **Active Patching** | Правая панель | Текущий роутинг на пульте с горизонтальными метрами; кнопка Обновить |

### Таблица Active Patching

Отображает текущее состояние input patching на пульте:

| Столбец | Содержимое |
|---|---|
| Канал | Номер входного канала (1–48), стерео-пары объединены (например, «3-4») |
| Название | Имя канала (из ParamData), «—» если не задано |
| Источник | Local / dSk / SLink / USB / I/O Port |
| Вход | Номер входа в пределах источника (1-based) |
| Уровень | Горизонтальный бар уровня сигнала с индикатором клиппинга |

- Стерео-пары отображаются одной строкой с двумя барами (L и R);
- Данные обновляются в реальном времени через UDP-поток метров;
- При наведении на бар — всплывающая подсказка с точным значением в дБ.

### Таблица Input Patching

Редактируемая таблица с селекторами для настройки инпатчинга:

| Столбец | Содержимое |
|---|---|
| ☑ (отметка) | Чекбокс — отмечает канал для Upload на пульт |
| Канал | Номер входного канала (стерео-пары объединены) |
| Название | Имя канала (read-only) |
| Источник | Селектор: Local / dSnake / SLink / USB / I/O Port |
| Вход | Селектор номера входа (зависим от выбранного источника) |

- При смене источника чекбокс автоматически ставится;
- Номера входов для Local включают XLR-каналы, ST1–ST3 (линейные стерео-пары
  на 1/4" и 3.5 мм), а также Talkback-микрофон;
- Селектор «Выбрать все» в заголовке — управляет всеми чекбоксами.

### Панель управления (центр)

| Элемент | Роль |
|---|---|
| **A** / **B** | Переключение между двумя пресетами инпатчинга |
| **Swap** (↔ кнопка) | Быстрая смена роутинга: загружает на пульт противоположный пресет |
| **← Download** | Загружает текущий роутинг пульта в Input Patching |
| **→ Upload** | Отправляет отмеченные каналы из Input Patching на пульт |
| **≈ Синхронная прокрутка** | Синхронизирует прокрутку обеих таблиц |

### Кнопки панели Input Patching

| Кнопка | Роль |
|---|---|
| 💾 Сохранить | Открывает модальное окно для сохранения текущего роутинга |
| 📂 Загрузить | Открывает модальное окно со списком сохранённых роутингов |

### Кнопка Active Patching

| Кнопка | Роль |
|---|---|
| ↻ Обновить | Повторно запрашивает полный дамп роутинга у пульта |

## 3. Стерео-слияние

### Логика объединения

Стерео-линкованные каналы (определяются из таблицы стерео-линков ParamData)
отображаются **одной строкой** в обеих таблицах:

| Тип | Отображение | Пример |
|---|---|---|
| Стерео-пара | «3-4» (левый b3 — правый b3+1) | Ch3 и Ch4 → строка «3-4» |
| Моно-канал | «7» (номер канала) | Ch7 → строка «7» |
| Local стерео-пара | «ST1», «ST2», «ST3» | ST1 L/R → строка «ST1» |
| Local Talkback | «Talk» | Talkback → строка «Talk» |

- Правая сторона пары **пропускается** — патчится только мастер-канал;
- В селекторе «Вход» для стерео-пары показываются пары: «1-2», «3-4», «ST1» и т.д.;
- Значение селектора — 0-based индекс левого канала.

### Локальные источники

Для Local-источника (source = `0x01`) селекторы содержат:

| Канал | Метка | Позиция |
|---|---|---|
| 1–XLR inputs | «1», «2», … | 0-based 0..xlrInputs-1 |
| ST1 L/R | «ST1 L», «ST1 R» | 0-based 48, 49 |
| ST2 L/R | «ST2 L», «ST2 R» | 0-based 50, 51 |
| ST3 L/R | «ST3 L», «ST3 R» | 0-based 52, 53 |
| Talkback | «Talk» | 0-based 58 |

Количество XLR-входов зависит от модели: SQ-5: 16, SQ-6: 24, SQ-7: 32.

### Максимальные номера входов

| Источник | Код | Всего входов | Нумерация |
|---|---|---|---|
| Local | `0x01` | XLR + ST1–ST3 + Talk | 1-based, с пропусками |
| dSnake / SLink | `0x02` | 48 | 1–48 |
| USB | `0x03` | 32 (SQ-5/6/7) | 1–32 |
| I/O Port | `0x04` | 64 | 1–64 |

## 4. Пресеты A/B

### Концепция

Два независимых пресета **A** и **B**, каждый хранит:
- Список каналов с их источниками и входами (`EditRow[]`);
- Конфигурацию стерео-пар (`number[][]`).

### Поведение

- При переключении текущий экран **сохраняется** в активный слот;
- Целевой слот **инициализируется из текущего роутинга пульта** при первом
  посещении (а не из активного пресета);
- При подключении к пульту оба слота заполняются из текущего роутинга;
- Кнопка **Swap** загружает на пульт противоположный пресет (если был A →
  загружает B, и наоборот);
- Кнопка Swap **активна** только когда пресеты A и B различаются.

### Отображение

- Заголовок Input Patching показывает текущий пресет: «Input Patching · A»
  или «Input Patching · B» (с цветовой маркировкой);
- Заголовок Active Patching показывает, какой пресет был последним
  загружен на пульт: «Active Patching · A» или «Active Patching · B»;
- После Upload/Download заголовки мигают соответствующим цветом.

## 5. Upload / Download

### Upload (→)

Отправляет отмеченные каналы из Input Patching на пульт:

1. Считываются все строки с отмеченным чекбоксом;
2. Для каждой строки отправляется `setInputPatch(destB3, source, sourceChannel)`;
3. Стерео-пары отправляют оба канала (L → N, R → N+1);
4. Заголовок Active Patching мигает цветом текущего пресета;
5. Поле «последний загруженный пресет» обновляется.

**Ограничения Upload:**
- Заблокирован, если таблицы Input и Active Patching совпадают;
- Заблокирован, если конфигурация стерео-пар в Input Patching отличается
  от конфигурации на пульте (заголовок подсвечивается красным с подсказкой);
- Если ни один канал не отмечен — показывается сообщение «Не выбран ни один канал».

### Download (←)

Загружает текущий роутинг пульта в Input Patching:

1. Запрашивается полный снапшот через `getSnapshot()`;
2. Таблица Input Patching пересоздаётся из полученных данных;
3. Текущий пресет (A или B) заменяется загруженными данными;
4. Сibling-слот (если пуст) инициализируется из роутинга пульта;
5. Заголовок Input Patching мигает зелёным.

**Ограничения Download:**
- Заблокирован, если таблицы Input и Active Patching уже совпадают.

### Кнопка «Обновить»

Повторно запрашивает полный дамп роутинга у пульта (переподписка на параметры).
Вызывает пересылку всего состояния пульта, включая роутинг и имена каналов.

## 6. Сохранение / Загрузка роутинга

### Сохранение

Модальное окно «Сохранить текущий роутинг»:

| Элемент | Роль |
|---|---|
| Текстовое поле | Имя снапшота (по умолчанию: «гггг.мм.дд {сцена}») |
| «Сохранить» | Сохраняет текущий Input Patching в localStorage |
| «Отмена» | Закрывает модальное окно |

**Данные сохранения:**
- Имя, временная метка (ISO), модель пульта;
- Список каналов (`EditRow[]`) — чекбоксы сбрасываются при сохранении;
- Конфигурация стерео-пар из Input Patching (или из пульта, если таблица пуста);
- Хранится в `localStorage` под ключом `sq_saved_routing`;
- Максимум **100** записей (старые удаляются).

### Загрузка

Модальное окно «Загрузить роутинг»:

| Элемент | Роль |
|---|---|
| Список сохранённых | Название, дата/время, модель; выделение текущей записи |
| «×» (удалить) | Удаляет запись из списка |
| «Не обращать внимание на конфигурацию» | Разрешает загрузку при несовпадении моделей или стерео-пар |
| «Загрузить» | Загружает выбранный снапшот в Input Patching |
| «Отмена» | Закрывает модальное окно |

**Поведение:**
- Двойной клик по записи — быстрая загрузка;
- Загрузка заменяет данные **текущего** пресета (A или B);
- Снапшот **не отправляется** на пульт — только заполняет Input Patching;
- Стерео-пары загружаются из сохранённой записи;
- Различия конфигураций (модель или стерео-пары) показываются меткой
  «Отличие конфигураций»; кнопка «Загрузить» блокируется до подтверждения
  через чекбокс.

## 7. Уровневые метры (Active Patching)

### Горизонтальные бары

На каждой строке Active Patching — горизонтальный бар уровня сигнала:

| Тип строки | Кол-во баров | Источник данных |
|---|---|---|
| Моно-канал | 1 | `inputs[b3]` |
| Стерео-канал | 2 (L, R) | `inputs[b3L]`, `inputs[b3R]` |

### Шкала

Одна шкала для всех вкладок (shared `meters.ts`):
- Диапазон: −60…0 дБФС → 0–100% ширины бара;
- ≥ −20 дБ: жёлтый (`meter-warn`);
- ≥ −6 дБ: красный (`meter-hot`);
- Клип (> 0 дБ): индикатор `.meter-clip.on`.

### Всплывающая подсказка

- При наведении на ячейку бара — кастомная подсказка с точным значением в дБ;
- Для стерео-пар показываются обе стороны: «L −12.3 dB», «R −12.1 dB»;
- Подсказка обновляется в реальном времени (live) пока курсор на баре;
- Подсказка скрывается при прокрутке таблицы.

### Кеширование по кадрам

UDP-поток метров приходит на 25–50 Гц. Renderer кеширует последний пакет
(`pendingMeters`) и применяет его в `requestAnimationFrame` — одна операция DOM
на каждый кадр экрана.

## 8. Синхронная прокрутка

Кнопка **≈** включает/выключает синхронизацию прокрутки двух таблиц:
- При прокрутке Input Patching прокручивается и Active Patching;
- При прокрутке Active Patching прокручивается и Input Patching;
- Защита от зацикливания: программная прокрутка не вызывает обратную
  прокрутку (guard через `requestAnimationFrame`);
- При включении таблицы немедленно выравниваются.

## 9. Заморозка Input Patching

### Жизненный цикл

1. **Подключение**: Input Patching заполняется из начального потока данных
   пульта (обновляется при каждом снапшоте);
2. **Начальный шторм завершён** (`onInitialState`): таблица **замораживается** —
   дальнейшие изменения на пульте не затрагивают Input Patching;
3. **Замороженная таблица**: селекторы источников и входов остаются
   редактируемыми; данные о именах каналов обновляются.

### Причины

Заморозка позволяет пользователю редактировать Input Patching параллельно
с работой на пульте — изменения на пульте не сбивают настройки селекторов.

## 10. Протокол и данные

### Команды, отправляемые на пульт

| Команда | Где в коде | Назначение |
|---|---|---|
| `setInputPatch(destB3, source, sourceChannel)` | `sendPatchesToConsole()` | Патч источника на канал микшера |
| `getSnapshot()` | `downloadInputPatching()`, `confirmLoadRouting()` | Запрос полного снапшота роутинга |
| `requestDump()` | кнопка «Обновить» | Повторный запрос полного дампа |

### Формат патч-кадра (из SQ-PROTOCOL.md)

```
F7 0B 0B 0D [ch] [modifier] [valLo] [valHi]
```

| modifier | Тип | Поля |
|---|---|---|
| `0x01`–`0x04` | Input patch | `ch` = канал источника, `valLo` = destB3, `valHi` = `0x20` |

### Коды источников

| Код | Источник |
|---|---|
| `0x01` | Local |
| `0x02` | dSnake / SLink |
| `0x03` | USB |
| `0x04` | I/O Port |

### Адресное пространство назначений (destB3)

| Диапазон | Назначение |
|---|---|
| `0x00`–`0x2F` | Input 1–48 |

### Поток метров (`MetersPayload`)

| Поле | Источник | Применение |
|---|---|---|
| `inputs[]`, `clip[]` | UDP 0x06/0x17 | Горизонтальные бары Active Patching |

## 12. Известные ограничения

1. **Input Patching замораживается** после начального шторма — изменения
   пульта в реальном времени не отражаются в таблице (только через
   кнопку «Обновить» или Download);
2. **Upload не отслеживает** изменения, внесённые на пульте после
   последнего Download — работает с теми данными, что в таблице;
3. **Сохранённые роутинги** хранятся в localStorage — недоступны при
   работе через разные профили Electron;
4. **Upload блокируется** при несовпадении конфигурации стерео-пар между
   Input Patching и Active Patching — патчинг был бы некорректным;
5. **Swap блокируется** при несовпадении конфигурации стерео-пар целевого
   пресета с текущей конфигурацией пульта;
6. **FX returns** не отображаются в таблицах — input patching ограничен
   48 входными каналами (b3 `0x00`–`0x2F`);
7. **Число сохранённых роутингов** ограничено 100 записями.
