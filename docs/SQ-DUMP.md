# sq-dump — CLI-тула для дампов ParamData

Автономная CLI-тула для контролируемых дамп-экспериментов с пультом SQ
(Приложение для дампа не нужно, Electron не требуется). Используется для
реверс-инжиниринга настроек пульта: дамп до изменения, одно изменение,
дамп после — diff указывает прямо на поле, кодирующее настройку.

Результаты уже проведённых экспериментов (состав шин, стерео миксов и матриц,
SQ-5 fw 1.6) перенесены в [`SQ-PROTOCOL.md`](SQ-PROTOCOL.md) §8.5.

## 1. Команды

```bash
npm run sq-dump -- capture 192.168.1.30 --label baseline   # дамп + отчёт
# …меняем ОДНУ настройку на пульте…
npm run sq-dump -- capture 192.168.1.30 --label experiment
npm run sq-dump -- diff pd-dumps/pd-*-baseline.bin pd-dumps/pd-*-experiment.bin
npm run sq-dump -- info pd-dumps/pd-…-baseline.bin         # полный отчёт диагностики
```

| Команда | Что делает |
|---|---|
| `capture <host> [port]` | подключается, ждёт flood ParamData (~97 КБ), сохраняет `.bin`-дамп и `.txt`-отчёт, отключается |
| `diff <a.bin> <b.bin>` | побайтовый diff с человекочитаемой расшифровкой каждого изменившегося офсета |
| `info <file.bin>` | полный отчёт диагностики стерео/линков по одному дампу |

Опции `capture`: `--out <dir>` (по умолчанию `pd-dumps/`), `--label <name>`,
`--timeout <ms>` (по умолчанию 15000).

`capture` печатает дайджест в терминал: состав шин (`@61/@65`), битмаску
стерео миксов (`@90..91`), спаренные матрицы (`@93`) и липкие A-метки
(вторичный след). Дампы пишутся в `pd-dumps/` (git-ignored) с меткой времени
и `--label`.

## 2. Методика эксперимента

1. `capture` — baseline (исходное состояние show).
2. Меняем **ровно одну** настройку на пульте.
3. `capture` — экспериментальный дамп.
4. `diff A B` — если настройка кодируется в ParamData, diff укажет на
   конкретный офсет; при чистом эксперименте «шум» минимален. Посторонние
   изменения — от живого сигнала/фейдеров.

## 3. Как читать diff

- **Шапка блоба:** `@61/@65` — состав шин (group/aux), `@90..91` — битмаска
  стерео 12 миксов (u16LE, bit i = Mix i+1), `@93` — битмаска спаренности
  матриц (bit 3/4/5 = пара 1/2/3). См. `SQ-PROTOCOL.md` §8.5.
- **Блок канала:** `884 + b3·336`; `+331` — «липкий» послотовый флаг
  (**не** стерео), `+332` — флаги (bit0 полярность, bit1 mute).
- **Стерео-линки входов** — таблица `81548` (encoding A/B, см.
  `src/main/stereo-links.ts`).
- **Приоритет источников:** авторитет — шапка `@61/@65/@90..93`; «липкие»
  поля (`+331`, encoding-A-пары) — только вторичная форензика: они не
  обновляются при пересоздании шин и не всегда возвращаются при обратном
  переключении.

## 4. Ограничения

- Основное приложение (не тула) пишет дамп **один** раз за соединение; для
  нового дампа нужно переподключение. Туле это не важно — каждый `capture`
  сам открывает и закрывает соединение.
- macOS-пути дампов приложения (если используется оно):
  `~/Library/Application Support/sq-router-control/diagnostics/`.
