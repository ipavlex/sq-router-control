## 0. Как пользоваться

**Статусы:**

| Метка | Значение |
|---|---|
| `[ ]` | не начато |
| `[~]` | в работе |
| `[x]` | готово |
| `[-]` | отменено / неактуально |

**Правила:**

- Один пункт — одна атомарная правка. Не объединять несвязанные изменения.
- ID не переиспользуется даже после отмены пункта.
- При статусе `[x]` дописывать короткий результат (PR/коммит) и снимать
  актуальность с исходного TODO в профильном документе.
- Пункты внутри группы независимы и допускают параллельное выполнение.

**База проверки (без пульта):**

- `npm test` — юнит-тесты чистых декодеров (`node:test` + `tsx`), без пульта и
  Electron. Покрытие ограничено чистыми функциями; UI и wire-логика — вручную.
- Доступные способы проверки: **демо-режим** (полная симуляция SQ-5,
  `src/main/demo-meters.ts`), `npm run typecheck`, `npm test`, `npm run build`,
  ручной UI.
- Всё, что упирается в неизвестный wire-format, без пульта проверить нельзя —
  такие задачи вынесены в группу B.

**Легенда групп:**

- **A** — можно сделать и проверить без пульта (UI / логика / localStorage / демо).
- **B** — требует реального пульта (реверс-инжиниринг или поведение на железе).
- **C** — гибрид: код пишется без пульта, финальная проверка — на сети/железе.

    таргетится на Grp1–4 по `0x48–0x4B`, на Aux1–8 по `0x58+`; (3) в регионе

    имена `groupNames` из снапшота, метка `Group N` в `b3ToLabel`, демо).

- [x] **MON-B4 — Реальное определение стерео-миксов** (`MONITOR-TAB.md` §13,
  `SQ-PROTOCOL.md` §8.5/§10.2).
  - **Сделано в v1.18.0:** режим моно/стерео микса читался из байта `+331`
    336-байтового блока канала.
  - **Исправлено 2026-10-15 (вечер):** гипотеза «+331 = стерео» опровергнута
    контролируемыми дампами — это липкий послотовый флаг. Стерео миксов
    кодируется **битмаской шапки `@90..91`** (u16LE, bit i = Mix i+1);
    `decodeMixStereoPairs` переведён на неё (каждая стерео-шина —
    самостоятельная пара `[i, i]`, соседние не сливаются). Полярность и
    обратимость подтверждены переключением Mix 1 (`0xFFE0 ↔ 0xFFE1`).
- [x] **MON-B5 — Режим матриц (стерео/моно) и имена слотов разбитых матриц**
  (`MONITOR-TAB.md` §12 п.5, §13).
  - **Найдено 2026-10-15 (вечер):** режим матриц кодируется **битмаской шапки
    `@93`** (bit 3/4/5 = спарена пара 1/2/3: `0x73+0x76`, `0x74+0x77`,
    `0x75+0x78`). Матрицы SQ-5 — 6 моно-шин; стерео-матрица занимает две
    (L+R, имя в L-слоте), разбиение освобождает R-шину как новую
    моно-матрицу (3 стерео → 6 моно в меню). Подтверждено переключениями
    всех трёх пар (`0x38→0x30→0x20→0x00→0x08`). Декодер
    `decodeMatrixStereoPairs` добавлен в `stereo-links.ts`; A-пары в
    link-регионе — липкий вторичный след (не возвращаются при обратном
    спаривании).
  - **Закрыто (UI):** `decodeMatrixStereoPairs` потреблён в «Мониторе».
    Цепочка: `connection` эмитит `matrixStereoPairs` → `RoutingModel` →
    снапшот (`matrixStereoPairs`, b3-пары) → IPC → `monitor.
    updateMatrixStereoPairs`. Кнопки матриц строятся из пар чистой функцией
    `matrixButtonSpecs` (`matrix-names.ts`, эвристика `matrixButtonLabels`
    удалена): гангованная пара → стерео-кнопка (L-слот → L-выход, R-слот →
    R-выход), свободный слот → моно-кнопка (шина в оба выхода). Число кнопок
    3–6 по состоянию пульта. Попутно исправлена раскладка слотов:
    `b3ToLabel` (и REAPER-экспорт) переведены на кросс-пары (L =
