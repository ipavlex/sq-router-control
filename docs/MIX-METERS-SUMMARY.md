# Миксы и Main LR на монитор-вкладке — описание работы

> Подробное описание работы ветки `feature/mix-meters`: что сделано, как устроен
> протокол метров, какие решения приняты. Оперативный статус и план — в
> соседнем файле [`BRANCH-PLAN-mix-meters.md`](BRANCH-PLAN-mix-meters.md).
> Последнее обновление: 2026-09-10 (коммит `e031a0b`).

## Цель

Показывать уровни сигнала (метры) не только входных каналов, но и **миксов 1–12
и Main LR** на кнопках вкладки «Монитор» — вертикальные бары, как у каналов.

- демо-режим — синтез (сделано в `65ac08a`);
- живой режим — декодирование реального UDP-формата (сделано здесь).

## Что сделано

### Живой декодер шин (id=0x18)

- `decodeBusLevel` + ветка `id=0x18` в `src/main/meters.ts`.
- Состояние шин (`busMeters`) хранится отдельно и **мержится в каждый**
  `MetersPayload` (`mergeMeters`), чтобы миксы текли в рендерер непрерывно
  между 0x18-пакетами (пульт шлёт их заметно реже входных).
- `resetMeters()` чистит шины вместе с остальным (переподключение, смена пульта).
- UI изменений не потребовал: бары на кнопках Mix/Main LR уже читали
  `mixes`/`mainLR` из демо-ветки; метки «demo mode only» в типах убраны.

### Диагностика метро-пакетов (охотничий инструментарий)

Оставлена в коде сознательно — пригодится для остальных недекодированных форматов.

- `meters.ts`: `meterSamplePreview` (dB-снимок), `diffMeterBody`/`formatMeterChanges`
  (`chg:` — карта изменений между соседними пакетами), `hotMeterSlots` (`hot:` —
  самые громкие слоты недекодированной формы).
- `connection.ts`: `_noteMeterPacket` — инвентаризация форматов (id + длина +
  decoded?) + периодический ре-сэмпл (4 с, `METER_SAMPLE_INTERVAL_MS`);
  `_meterSampleAt`/`_meterPrev`/`_meterRawSaved`.
- `main.ts`: обработчик `meterPacketInfo` — **тихий режим**: строка в лог только
  при первом появлении формы или когда слоты реально сдвинулись (≥0.25 дБ).
- Сырые дампы недекодированных форм: `meter-packet-0x<id>-<len>B.bin` в
  `userData/diagnostics/` (один файл на форму пакета) — для оффлайн-анализа.

### Метки в журнале

Для корреляции действий на пульте со строками лога при захватах:

- кнопка «Метка (M)» + клавиша `M` (по `e.code`, только когда видима вкладка
  «Журнал»); отмеченные строки получают стиль `.line.mark`;
- файлы: `src/renderer/tabs/log/{index.ts,view.html}`, `core/{types.ts,utils.ts}`,
  `assets/styles.css`.

### Верификация

- Синтетический 0x18: Mix 3 = −12 дБ, Mix 12 = +1.5 дБ + клип, LR = −5 дБ;
  мерж с 0x17-инпутами; `resetMeters` — всё ок.
- **На реальном дампе** декодер выдал `mainLR = −4.84` дБ — музыка играла в LR,
  значение физически осмысленное.
- `npm run typecheck` + `npm run build` — чисто.

## Справочник: UDP-метры SQ

Проверено на SQ-5, FW 1.6.4812. Публичных данных нет (hrueger/allen-heath-sq-tools
помечает Metering как «UDP Only, format TBD») — всё снято реверсом.

### Формат пакета

`[0x7F] [id:u8] [len:u16LE] [00 00] [body]`, тело — u16 LE. UDP-порт приходит
в ответе на subscribe (sub=0x00).

### Кодировка значений (общая для всех метро-пакетов)

- дБФС = `(raw − 0x8000) / 256`;
- пол: `0x1201` (≈ −286 дБ — фактически «тишина»);
- клип: `raw > 0x8000` (> 0 дБФС);
- заглушки-данные: `0x0000` и `0xFFFF` — уровнем не считать.

### Известные id

| id | Тело | Содержимое |
|---|---|---|
| 0x05 | 0 B | keepalive |
| 0x06 | 1056 B | 48 входов × 11 слотов (декодируется) |
| 0x07 | 1416 B | 6 заголовка + 39 шин × 18 слотов; те же шины по 2 записи на шину, у нечётных записей офсет ~+0.1 дБ (пик-латч?) — не декодирован |
| 0x09 | 100 B | 50 значений, миксов не содержит |
| 0x16 | 1168 B | те же шины/слоты, что 0x18, но на ~10 дБ тише (пре-фейдерные тапы) + хвост с параметр-данными (сентинелы 0xFFFF, константы +17…+18) — не декодирован |
| 0x17 | 96 B | 48 входов (декодируется) |
| **0x18** | **480 B** | **40 шин × 6 слотов — источник живых миксов (декодируется)** |

### Раскладка 0x18 (40 шин × 6 u16)

| Шины | Слоты | Содержимое |
|---|---|---|
| 0–22 | 0–137 | входы b3 0–22 (здесь не используются — входы уже в 0x06/0x17) |
| **23** | **138–143** | **Main LR** |
| **24–35** | **144–215** | **Mix 1–12** (шина = 23 + номер микса) |
| 36–39 | 216–239 | FX send 1–4 |

Уровневые слоты внутри 6-слотного блока шины: **две L/R-пары — [s0, s1] и
[s3, s4]** (слот s2 = `0x0000`, s5 = `≥0xF000` заглушка). Пары — два измерительных
тапа одной шины (значения близки, но не равны); по стороне берётся максимум
(`BUS_LR_OFFSETS` в байтах = [[0,2],[6,8]]).

Раскладка подтверждена изолированными захватами с метками: Mix 1 → Mix 5 →
Mix 12; музыка в LR.

### Стерео-режим миксов (2026-09-10, живой пульт)

На SQ миксы не «линкуются» как каналы — у шины есть **режим стерео/моно**
(стерео-микс занимает один слот Metering, шины не сдвигаются). Поведение в 0x18:

- **стерео-микс**: s0 ≠ s1 (L ≠ R, например −14.5 / −18.2); шина-партнёр (Mix 2
  при стерео Mix 1) — на полу;
- **моно-микс**: s0 == s1 бит-в-бит (−14.2 / −14.2), вторая пара на полу;
- **Main LR**: всегда L ≠ R.

UI: у Main LR всегда два бара; у микса — два бара, если он стерео. Стерео
определяется двумя путями: из snapshot (`mixStereoPairs`, декодер таблицы линков
в ParamData) или **поведенчески** — защёлка при наблюдении расхождения L/R
≥0.4 дБ (моно даёт бит-равные стороны, так что ложных срабатываний нет; стерео
с моно-контентом ловится с задержкой). Признак держится до конца сессии.

Открытый вопрос: где в ParamData лежит бит режима стерео/моно миксов. Таблица
линков (входная часть, офсет 81548) режим не отражает; **ловушка**: записи
входов на индексах 44–47 (Ch45-48, реальные стерео-пары — подтверждено) несут
кодировку B со slot-id 0x58–0x5b, численно совпадающими с b3 миксов — их легко
принять за self-target миксов и «урезать» скан (сначала так и сделали, на
пульте это сломало отображение Ch45-48; откатено). Расширение таблицы за
входами (FX returns, мастера) не декодируется.

## Ключевые решения

1. **Реверс через изолированные захваты**, а не спекулятивный декодер — исследование
   показало, что формат нигде не опубликован; инструменты сбора (метки, тихий режим,
   дампы) сделали финальный захват однозначным.
2. **Максимум из 4 уровневых слотов** на шину — пары L/R близки, max надёжен для бара.
3. **Отдельное состояние `busMeters` + мерж в каждый payload** — миксы не «мигают»
   между редкими 0x18-пакетами.
4. **Тихий режим лога** — строка только при первом появлении формы или сдвиге слотов
   ≥0.25 дБ; без этого лог утопал в повторах.
5. **Диагностику оставить** — дампы/снимки дёшевы и нужны для 0x07/0x16 в будущем.

## Ловушка для тестов

6-байтовый заголовок UDP-пакета = 3 u16-слота: запись в слот 0 «тела» затирает
`msg[0]/msg[1]`. Тестовые сообщения собирать только через
`Buffer.concat([header, body])`.
